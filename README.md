# AniSeeker-mini-app

AniSeeker 0.1 — Telegram Mini App с вертикальной лентой досье, поиском по имени, избранным и экраном профиля. Первая карточка посвящена Лайту Ягами. Три остальные карточки тестовые. Для портретов используются CSS-заглушки.

## Локальный запуск

Требуется Node.js 22.12+ в ветке 22.x или Node.js 24.x.

```bash
npm ci
npm run dev
```

Откройте адрес из вывода Vite, обычно `http://localhost:5173`. Для проверки на телефоне в той же сети запустите `npm run dev -- --host 0.0.0.0` и откройте адрес `Network` из вывода Vite.

Для проверки production-сборки:

```bash
npm run build
npm run preview
```

## Что проверить

1. Пролистайте карточки вверх и вниз. На компьютере работают колесо мыши, стрелки при фокусе на ленте и кнопка-подсказка под карточкой.
2. Нажмите лупу и введите «ягами». Откройте результат, вернитесь в поиск, затем закройте его. Для проверки пустого результата введите имя, которого нет в ленте.
3. Сохраните карточку закладкой. Откройте «Избранное», обновите страницу и снова откройте вкладку. Карточка должна сохраниться. Удалите её закладкой.
4. Откройте «Профиль» и вернитесь на «Главную». Браузер и каждый Telegram-аккаунт используют собственный профиль. Имя «Гость» отображается, пока пользователь не сохранит никнейм.
5. Нажмите «Изучить персонажа». Проверьте заголовок, заглушку изображения и блок «Материалы». Кнопка возврата закрывает досье. Из поиска или избранного возврат ведёт к исходному экрану.

Избранное доступно в локальном хранилище. У авторизованных Telegram-аккаунтов оно также синхронизируется с Supabase.

## Шахматный тренажёр

Откройте «Стратегию» из досье Лайта Ягами. Текущая попытка и пройденные испытания сохраняются в `localStorage`. Команда `npm run test:strategy` проверяет стартовые позиции, подготовленные ответы и альтернативные решения с помощью Chess.js.

## Публикация через Vercel

1. Импортируйте репозиторий в Vercel. Выберите пресет **Vite** и Node.js 24.x.
2. Укажите команду сборки `npm run build` и выходную папку `dist`. Для облачных аккаунтов выполните настройку ниже.
3. После публикации скопируйте HTTPS-адрес. В BotFather установите этот адрес для кнопки меню своего бота через `/setmenubutton` или укажите его в настройках Main Mini App.
4. Откройте приложение из бота в Telegram на iOS и Android. Проверьте безопасные области, свайпы по ленте, открытие поиска с клавиатурой и системную кнопку «Назад» при открытом досье.

SDK подключён в `index.html`. Порядок выбора области хранения описан в разделе «Пользовательские данные».

## Структура

| Путь | Назначение |
| --- | --- |
| `src/App.tsx` | Состояние экранов, поиск и связи между лентой, досье и вкладками |
| `src/components/` | Карточка, заглушка портрета, SVG-иконки и навигация |
| `src/screens/` | Лента, списки, досье и профиль |
| `src/data/characters.ts` | Модель персонажа, тестовые данные и поиск |
| `src/hooks/useFavorites.ts` | Локальное избранное |
| `src/platform/telegram.ts` | Интеграция с Telegram и безопасными областями |
| `src/styles.css` | Адаптивная раскладка, стеклянные поверхности и переходы |

Карточки и списки получают типизированные данные через свойства. Каталог персонажей остаётся частью приложения. Supabase хранит только приватные данные аккаунтов.

## Пользовательские данные

Сервер проверяет HMAC подписанной строки `Telegram.WebApp.initData` и возраст данных запуска (до часа). Подписанная сессия действует до 12 часов и хранится в памяти Mini App. После истечения срока сессии может потребоваться заново открыть приложение из бота. `initDataUnsafe.user.id` используется только для выбора локальной области.

Браузерный профиль остаётся локальным. Telegram-профиль загружает снимок состояния при входе. Изменения сохраняются на устройстве и отправляются пакетами, когда доступен интернет. Аватар загружается только при открытии профиля и кэшируется в IndexedDB. Текущую аватарку может запросить только её владелец через API. При замене или удалении прежний файл становится недоступен через API, а сервер запрашивает его удаление из закрытого бакета.

Данные каждого аккаунта записываются в отдельные профили и разделы Supabase. При конфликте одновременных изменений одной записи сохраняется уже принятая сервером версия. Последний конфликтующий локальный вариант остаётся на устройстве под ключом `aniseeker:user:telegram:<id>:cloud:v1:conflict:<key>`. Изменения разных записей применяются независимо.

### Настройка Supabase и Vercel

1. В Supabase откройте **SQL Editor → New query**, вставьте весь [supabase/aniseeker.sql](supabase/aniseeker.sql) и нажмите **Run**. Скрипт создаёт таблицы, функции для сохранений, правила доступа и закрытый бакет `aniseeker-avatars`. Повторный запуск сохраняет существующие данные.
2. В Vercel откройте **Project → Settings → Environment Variables**. Добавьте перечисленные ниже переменные в **Production**. Для проверки Pull Request настройте эти же имена и в **Preview**, указав данные проекта и бота, которые будут использоваться для проверки.
3. После настройки запустите **Redeploy**. Если проверяете Preview, откройте именно этот HTTPS-адрес из Telegram через тестового бота, чей токен задан для Preview.
4. Проверьте один аккаунт на двух устройствах. Сохраните никнейм, аватар, персонажа в избранном и пройдите шаг тренировки. После синхронизации откройте Mini App на втором устройстве. Отдельно проверьте, что у другого Telegram-аккаунта свой профиль и пустые данные при первом входе.

| Переменная | Где получить |
| --- | --- |
| `VITE_SUPABASE_URL` | В Supabase откройте **Connect** и скопируйте **Project URL**. |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | В Supabase откройте **Settings → API Keys → Publishable key**. |
| `SUPABASE_SERVICE_ROLE_KEY` | В Supabase откройте **Settings → API Keys → Secret keys** и возьмите секретный ключ `sb_secret_…`. Существующий ключ `service_role` из **Legacy API keys** также поддерживается. |
| `TELEGRAM_BOT_TOKEN` | Возьмите токен того бота, через которого открывается AniSeeker, в **@BotFather → /mybots → API Token**. |
| `ANISEEKER_SESSION_SECRET` | Сгенерируйте случайное значение командой `openssl rand -hex 32`. |

Последние три переменные используются только внутри Vercel Functions. Добавляйте их в Vercel как секреты, без префикса `VITE_`. Клиент обращается к собственному API, где на каждом запросе проверяется подпись сессии. Supabase RLS и права доступа закрывают таблицы и аватарки для прямых клиентских запросов.

### Перенос локальных сохранений

После входа в Telegram на устройстве со старыми сохранениями откройте **Профиль → Перенести сохранения** и подтвердите **Это мои сохранения**, если данные принадлежат вам. Приложение переносит только ключи текущего подтверждённого аккаунта, которых ещё нет в облачном профиле. Исходные записи и аватар остаются на устройстве. Браузерный профиль и старые общие ключи требуют отдельного восстановления.

### Восстановление сохранений до разделения аккаунтов

В общих ключах старого формата нет Telegram ID владельца. Приложение оставляет общие ключи и записи аватарок на месте. Для переноса нужен независимо подтверждённый ID первоначального владельца. Текущий сеанс и совпавший никнейм сами по себе владение не подтверждают.

1. Сопровождающий подтверждает владельца по ранее известным сведениям и открывает AniSeeker от имени этого владельца на устройстве и в том браузерном контексте, где находятся старые данные.
2. На главном экране закройте другие окна AniSeeker. Запустите локально проверенный сниппет [restore-legacy-profile.js](scripts/restore-legacy-profile.js) в DevTools страницы владельца, заменив `verifiedOwnerId = 0` независимо подтверждённым числовым ID. Сниппет сверит ID с текущим Telegram SDK, закрепит старую область за владельцем и скопирует данные в свободные ключи. Аватар копируется до записи ссылки на него в профиле.
3. Перезагрузите приложение. После входа используйте «Перенести сохранения» в профиле. Существующие записи выбранного аккаунта имеют приоритет, исходные записи остаются на устройстве. Если перенос прервался, его можно повторить для того же владельца. Если владельца подтвердить не удалось, оставьте старые записи на месте.
